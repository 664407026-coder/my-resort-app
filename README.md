# I-Thara Cloud

ระบบจัดการที่พักบนเว็บสำหรับดูสถานะห้อง บันทึกรายรับรายจ่าย และติดตามกำไรหรือขาดทุน ใช้ **Firebase Authentication** สำหรับบัญชีผู้ใช้ และ **Cloud Firestore** สำหรับข้อมูลของแต่ละบัญชี หน้าเว็บเป็นไฟล์ static จึงเผยแพร่ด้วย GitHub Pages ได้โดยไม่ต้องมีเว็บเซิร์ฟเวอร์ของตนเอง

- เว็บที่เผยแพร่: https://664407026-coder.github.io/my-resort-app/
- GitHub repository: https://github.com/664407026-coder/my-resort-app
- Firebase project ในโค้ด: `my-resort-app-60d6e`

> การแก้ไฟล์ในเครื่อง **ยังไม่เปลี่ยนเว็บที่เผยแพร่** ต้อง commit ไฟล์ไปยัง repository และรอ GitHub Pages เผยแพร่ก่อน

## ความสามารถ

| หน้า | ทำอะไรได้ |
| --- | --- |
| แดชบอร์ด | ดูจำนวนห้องที่มีผู้พัก รายรับ รายจ่าย กำไร/ขาดทุนของเดือนที่เลือก และกราฟเทียบรายรับกับรายจ่ายย้อนหลัง 6 เดือน |
| จัดการห้องพัก | ค้นหาชื่อหรือประเภท กรองสถานะและประเภท เพิ่ม แก้ไข ลบ เช็คอิน เช็คเอาท์ และรีเซ็ตสถานะห้อง |
| รายรับรายจ่าย | เพิ่มหมวดหมู่และบันทึกค่าใช้จ่าย ดูรายการตามเดือน และลบรายการที่บันทึกผิด |
| ผู้ใช้งานระบบ | ดูอีเมล UID และวันที่บันทึกบัญชี เฉพาะผู้ใช้ที่มีสิทธิ์แอดมิน |

เว็บปรับเลเอาต์ตามขนาดหน้าจอ บนคอมพิวเตอร์กดปุ่มด้านซ้ายของแถบหัวเว็บเพื่อย่อหรือขยายเมนูด้านข้าง ระบบจำขนาดเมนูไว้ในเบราว์เซอร์นั้น บนจอเล็กปุ่มเดียวกันใช้เปิดหรือปิดเมนู รายรับถูกบันทึก **ตอนเช็คอิน** ส่วนการเช็คเอาท์เปลี่ยนสถานะห้องเท่านั้น ดังนั้นตัวเลขกำไร/ขาดทุนคือ *รายรับที่บันทึก − รายจ่ายที่บันทึก* ไม่ใช่งบการเงินตามเกณฑ์บัญชี

### สถานะห้องและประเภทห้อง

- การ์ดสีเขียวอ่อนคือห้องว่าง การ์ดสีแดงคือมีผู้เข้าพัก และการ์ดสีเหลืองคือครบ 24 ชั่วโมงแล้ว รอทำความสะอาด การ์ดทั้งใบกดได้ จึงเลือกห้องได้ง่ายขึ้นบนจอสัมผัส
- ค้นหาห้องจากชื่อหรือประเภท และใช้ตัวกรอง **สถานะ** กับ **ประเภท** เพื่อหาห้องเมื่อมีหลายห้อง
- ตอนเพิ่มหรือแก้ไขห้อง กด **เพิ่มประเภทห้องเอง** เพื่อระบุชื่อประเภทและราคาค้างคืน/ชั่วคราว ประเภทใหม่จะถูกเก็บในข้อมูลบัญชีนั้นและนำไปใช้กับห้องอื่นได้
- เมื่อครบ 24 ชั่วโมงหลังเช็คอินและยังไม่มีการเคลียร์ห้อง ระบบจะเปลี่ยนเป็น **ลูกค้าออกแล้ว รอทำความสะอาด** พร้อมแสดงแถบแจ้งเตือนบนหน้าจัดการห้องพัก หลังตรวจและทำความสะอาดแล้ว ให้กดการ์ดและเลือก **ทำความสะอาดเสร็จ เปิดห้องว่าง**
- การครบ 24 ชั่วโมงเป็นเงื่อนไขตามเวลา **ไม่ใช่การยืนยันว่าลูกค้าออกจริง** ผู้ดูแลควรตรวจห้องก่อนเปิดให้ลูกค้ารายใหม่ ระบบตรวจทุกนาทีขณะหน้าเว็บเปิดอยู่ และตรวจทันทีเมื่อเปิดหรือกลับมาที่เว็บ หากไม่มีใครเปิดเว็บ ณ เวลาครบกำหนด การเปลี่ยนสถานะและแจ้งเตือนจะเกิดเมื่อมีการเปิดเว็บครั้งถัดไป

## โครงสร้างไฟล์

| ไฟล์ | หน้าที่ |

## เริ่มใช้งานในเครื่อง

ต้องมี Node.js และอินเทอร์เน็ตเพื่อโหลด Firebase SDK, ฟอนต์ และไอคอน จากโฟลเดอร์ที่มี `index.html` ให้รัน:

```powershell
node scripts/dev-server.mjs
```

จากนั้นเปิด http://127.0.0.1:8000/ ในเบราว์เซอร์ ไม่ควรเปิด `index.html` ด้วย `file://` เพราะเว็บใช้ JavaScript modules

โค้ดใน `app.js` เชื่อมกับ Firebase project `my-resort-app-60d6e` อยู่แล้ว หากนำไปใช้กับโปรเจกต์ Firebase อื่น ต้องเปลี่ยนค่า `firebaseConfig` ให้ตรงกับโปรเจกต์นั้น

## สมัครสมาชิกด้วยอีเมล

1. ใน Firebase Console ของโปรเจกต์ `my-resort-app-60d6e` เปิด **Authentication → Sign-in method → Email/Password** แล้วบันทึก การเปิดวิธีเข้าสู่ระบบนี้เป็นการตั้งค่า Firebase และทำจากไฟล์เว็บไม่ได้
2. บนหน้าเว็บ กด **สร้างบัญชีใหม่ด้วยอีเมล** กรอกอีเมล รหัสผ่าน และยืนยันรหัสผ่าน
3. กด **สมัครสมาชิกด้วยอีเมล** เมื่อสำเร็จ Firebase จะเข้าสู่ระบบให้โดยอัตโนมัติ

หากสมัครไม่สำเร็จ หน้าเว็บจะแสดงสาเหตุที่ตรวจพบ เช่น อีเมลถูกใช้แล้ว รหัสผ่านไม่ผ่านเงื่อนไข เครือข่ายมีปัญหา หรือยังไม่ได้เปิด Email/Password ([คู่มือ Firebase](https://firebase.google.com/docs/auth/web/password-auth))

## นำเว็บขึ้น GitHub Pages

การใช้งานหน้าเว็บต้องมี `index.html`, `app.js` และ `styles.css` อยู่ **ระดับบนสุดของ repository เดียวกัน** เพราะ `index.html` อ้างอิงไฟล์อีกสองไฟล์ด้วย path แบบ `./`

วิธีอัปโหลดผ่านหน้าเว็บ GitHub:

1. เข้าสู่ระบบ GitHub แล้วเปิด [repository นี้](https://github.com/664407026-coder/my-resort-app) เลือกสาขา `main`
2. กด **Add file → Upload files** แล้วเลือก `index.html`, `app.js`, `styles.css` จากโฟลเดอร์โปรเจกต์ ไม่ต้องอัปโหลด ZIP
3. ใส่ข้อความ commit เช่น `Update resort dashboard and email signup` แล้วกด commit ไปยัง `main`
4. ตรวจ **Settings → Pages** ว่าแหล่งเผยแพร่เป็นสาขา `main` และโฟลเดอร์ `/(root)` จากนั้นรอการเผยแพร่แล้วรีเฟรชเว็บ

หากต้องการเก็บเอกสารและไฟล์ตั้งค่าไว้ใน GitHub ให้อัปโหลด `README.md`, `firebase.json`, `firestore.rules` และโฟลเดอร์ `scripts` เพิ่มได้ แต่ **GitHub Pages จะไม่ deploy Firestore Rules ให้** ต้องทำขั้นตอนถัดไปแยกต่างหาก ([วิธีอัปโหลดไฟล์](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository), [การตั้งค่า Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site))

## สิทธิ์ข้อมูลและหน้าแอดมิน

ข้อมูลห้องและรายการเงินอยู่ใน `resortData/{uid}` โดยแต่ละบัญชีอ่านและเขียนได้เฉพาะเอกสารของตนเอง รายชื่อบัญชีอยู่ใน `userProfiles/{uid}` การแสดงหรือซ่อนเมนูในหน้าเว็บ **ไม่ใช่การป้องกันข้อมูล** ต้อง deploy `firestore.rules` เพื่อบังคับสิทธิ์ที่ Firestore ด้วย

ก่อน deploy ให้ตรวจและรวมกฎนี้กับกฎเดิมของ Firebase project หากมีบริการอื่นใช้กฎเดิมอยู่ จากนั้นใช้ Firebase CLI:

```powershell
firebase login
firebase deploy --only firestore:rules --project my-resort-app-60d6e
```

หน้า **ผู้ใช้งานระบบ** จะปรากฏเมื่อบัญชีนั้นมี Firebase custom claim `admin: true` เท่านั้น การกำหนด claim ต้องทำผ่าน Admin SDK ฝั่งผู้ดูแล ห้ามทำจาก JavaScript ที่เผยแพร่บนเว็บ ([คู่มือ custom claims](https://firebase.google.com/docs/auth/admin/custom-claims))

ตัวอย่างคำสั่งใน PowerShell จากโฟลเดอร์โปรเจกต์:

```powershell
npm install --no-save firebase-admin
$env:GOOGLE_APPLICATION_CREDENTIALS = "C:\path\to\service-account.json"
node scripts/set-admin.mjs "PASTE_UID_HERE" "admin@example.com"
node scripts/backfill-profiles.mjs my-resort-app-60d6e
```

- หา UID จาก Firebase Console → Authentication → Users แล้วแทน `PASTE_UID_HERE` และ `admin@example.com` ด้วย UID กับอีเมลของบัญชีแอดมินจริง สคริปต์จะตรวจว่าตรงกันก่อนกำหนดสิทธิ์
- ให้แอดมินออกจากระบบและเข้าสู่ระบบใหม่เพื่อรับ token ที่มีสิทธิ์ล่าสุด
- สคริปต์ `backfill-profiles.mjs` นำบัญชีเดิมทั้งหมดจาก Firebase Authentication เข้ารายชื่อ และอัปเดตวันที่เป็นวันสมัครจริง หากไม่รัน บัญชีเดิมจะเริ่มปรากฏเมื่อกลับมาเข้าสู่ระบบ
- เก็บไฟล์ service account **นอกโฟลเดอร์เว็บและนอก GitHub** ไม่ส่งกุญแจให้บุคคลอื่น

## ตรวจหลังเผยแพร่

1. เปิดเว็บจาก URL GitHub Pages แล้วกด **สร้างบัญชีใหม่ด้วยอีเมล** ตรวจว่ามีช่องยืนยันรหัสผ่าน
2. สมัครด้วยอีเมลที่ยังไม่เคยใช้ และตรวจว่าเข้าแดชบอร์ดได้
3. เพิ่มห้องและบันทึกรายจ่าย แล้วรีเฟรชหน้าเพื่อตรวจว่าข้อมูลยังอยู่
4. ลองย่อและขยายเมนูด้านข้าง เพิ่มประเภทห้องเอง และตรวจว่าค้นหา/กรองห้องได้ทั้งบนคอมพิวเตอร์และมือถือ
5. เข้าด้วยบัญชีทั่วไป: ต้องไม่เห็นเมนู **ผู้ใช้งานระบบ**; เข้าด้วยบัญชีแอดมิน: ต้องเห็นรายชื่อ
6. หากหน้าเว็บไม่เปลี่ยน ให้ตรวจสถานะใน GitHub **Actions/Pages** และรีเฟรชแบบไม่ใช้แคช

## ข้อจำกัดที่ควรทราบ

- โค้ดปัจจุบันเก็บห้องและธุรกรรมของผู้ใช้หนึ่งคนเป็น arrays ใน Firestore document เดียว เหมาะกับงานขนาดเล็ก หากรายการเพิ่มจำนวนมากหรือมีหลายคนแก้ข้อมูลบัญชีเดียวพร้อมกัน ควรย้ายเป็น subcollections
- การลบธุรกรรมไม่เปลี่ยนสถานะห้องโดยอัตโนมัติ หากลบรายรับที่เกิดจากเช็คอิน ให้ตรวจสถานะห้องแยกต่างหาก
- การลบห้องไม่ลบประวัติรายรับเดิม เพื่อให้รายงานย้อนหลังไม่หาย
